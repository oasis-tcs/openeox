# 3. Discussion

## 3.1 Updates

- Public review status
  - The OpenEoX Core Schema v1.0 CSD01 is now in public review; see issue #[203](https://github.com/oasis-tcs/openeox/issues/203) ("Invitation to comment on OpenEoX Core Schema v1.0 CSD01 - ends August 13th").
  - Stefan reported that no comments had been received yet on the ongoing public review (day three); no other member reported having received comments.
  - The public review runs for 30 days and ends on **13 August 2026** (end of day UTC).
  - Stefan noted the review was hard to get out and thanked those who worked on the publication.
  - Stefan mentioned Michael Coletta is increasingly taking over both technical and communication work, giving hope for progress on the API and the shell.
  - The specification reviewed reflects the release candidates leading to CSD01: PR #[199](https://github.com/oasis-tcs/openeox/pull/199) (CSD01 RC 2), PR #[201](https://github.com/oasis-tcs/openeox/pull/201) (CSD01 RC 3), and PR #[202](https://github.com/oasis-tcs/openeox/pull/202) (nits found in RC2).
- Tooling
  - The previous private tool chain relied on old software with a ~12 GB footprint and did not work reliably across systems.
  - It has been reduced to a small, easily installable, configuration-driven setup based on Pandoc, Typst, and one of Stefan's packages, removing the need for copies of scripts.
  - A single configuration now drives the front matter for all output formats (Markdown, HTML, PDF), avoiding the previous problem of keeping separate front matter in sync.
  - Typst is roughly ten times faster than LaTeX (about 4 seconds instead of a minute for a PDF), enabling faster editor turnarounds.
  - The setup makes it feasible to run checks via GitHub Actions, which was impractical with the previous 12 GB installation.
  - Stefan has offered the setup to other TCs working with Markdown so they can produce clean Markdown plus the three navigable output formats.
